# Artifact Extraction Contract (v1.2)

## Purpose

Define a deterministic, reproducible protocol for extracting persistent reasoning artifacts from completed reasoning runs.

This contract ensures that extracted artifacts are:

- structural (not procedural traces)
- reusable across similar tasks
- minimal and non-redundant
- safe for persistence

This document is the **single source of truth** for artifact extraction behavior.

---

## Core Principles

1. **Structure over reasoning**
   - Do not store reasoning traces
   - Store only structural constraints, decisions, procedures, or clarified goals

2. **Default = NONE**
   - Artifacts must NOT be generated by default
   - Absence of artifact is valid and expected

3. **No transient state**
   - Temporary values, intermediate steps, and local reasoning must not be stored

4. **No semantic overlap**
   - Each artifact must represent a distinct structural role

5. **Durability over novelty**
   - Only artifacts that remain valid across future reasoning runs are allowed

6. **Structural density**
   - Each artifact MUST encode at least one of:
     - rule
     - condition
     - invariant
     - transformation

7. **Independence**
   - Artifacts MUST NOT:
     - reference each other
     - depend on execution order
     - require joint interpretation

---

## Artifact Scope (Runtime)

Each artifact is assigned a scope at runtime (NOT part of prompt output):

- `local` (default) — applies within a specific scenario pattern
- `global` — reusable across domains and scenarios

Rule:

- `global` MUST be used only if reuse outside the scenario is clear and justified
- otherwise assign `local`

---

## Artifact Types

### TaskCard

Represents the task objective.

Use ONLY if:
- the goal is ambiguous or unclear
- reformulation reduces ambiguity

Otherwise:
- MUST be `NONE`

---

### DecisionCard

Represents a persistent decision affecting how the problem is approached.

Requirements:
- changes HOW the task is solved
- removes ambiguity in interpretation
- reusable across similar tasks

---

### ConstraintCard

Represents a rule that must never be violated.

Requirements:
- prevents a critical or common error
- enforces correctness deterministically
- MUST be explicit and checkable

Forbidden:
- vague rules ("be careful", "avoid mistakes")

---

### ProcedureCard

Represents a reusable deterministic workflow.

Requirements:
- defines a strict sequence of steps
- removes need for exploration or guessing
- typically ≤ 3 steps, up to 5 ONLY if necessary for determinism
- fully unambiguous

---

## Extraction Protocol

Artifacts MUST be extracted using the following process:

### Step 1 — Identify difficulty

- Where is the highest risk of error?
- Which part requires implicit interpretation?
- Where is reasoning fragile?
- Where would another system likely fail?

---

### Step 2 — Identify underlying structure

Convert difficulty into structure:

- implicit rules
- hidden order of operations
- state transitions
- invariant conditions
- **event triggers** (crossing, boundaries, reversals)

Trigger-based patterns are HIGH value.

---

### Step 3 — Extract artifacts

Rules:

- At most ONE artifact per type
- Each artifact must be independent
- No semantic overlap between artifacts

---

## Validation Rules

Each artifact MUST:

- reduce reasoning search space
- be reusable across similar tasks
- be concise (1–3 lines)
- NOT restate solution steps
- NOT depend on this exact instance
- encode explicit structure (see Structural Density)

---

## Rejection Rules

Artifacts MUST be rejected if they:

- are generic advice (e.g., "think step by step")
- describe intermediate states
- restate task instructions
- duplicate or partially overlap existing artifacts
- contain reasoning traces
- fail structural density requirement

If overlap is detected:
→ MUST output NONE

---

## Confidence Rule

If extraction confidence is not high:
→ MUST output NONE

---

## Invalid Examples

DecisionCard:
- "Think carefully before solving" ❌

ConstraintCard:
- "Avoid mistakes" ❌

ProcedureCard:
- "Do steps one by one" ❌

---

## Integration Rules

- Extraction runs AFTER reasoning is complete
- Extraction MUST NOT influence reasoning outcome
- Output is subject to artifact_filter validation
- Only accepted artifacts may be persisted

---

## Non-Goals

This contract does NOT:

- define storage format
- define governance or commit rules
- allow semantic interpretation
- allow merging or rewriting artifacts

---

## Contract Authority

This document defines artifact extraction behavior.

All implementations MUST conform to this contract.

No deviations allowed without explicit contract update.

---

## Summary

Artifact extraction is not generation.

It is a controlled transformation:

reasoning → structure

Only structure that survives beyond the current run is allowed to persist.
